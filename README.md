# ModuFarm — тепличные комплексы, сельхозроботы и проекты садов (ООО «Ключ «Гремячий», Крым)

Три страницы: **главная — тепличные комплексы** из блоков 10×100 м (основное направление с 16.10.2026), **«Роботы»** (`roboty.html`) — программы и сельхозроботы, **«Сады»** (`sady.html`) — проектирование садов. Цель — заявка; блок заявки внизу каждой страницы.

**Стек:** PHP 8.1+ без библиотек и без базы данных. Контент лежит в `data/*.json`, сборщик (`app/lib`, шаблоны `app/templates`) делает из него готовые HTML-страницы, админка (`app/admin`) правит JSON и сразу пересобирает сайт. Посетитель получает обычный статический HTML.

## Главное правило: один источник правды

- **Контент** (тексты, контакты, свидетельства, фото `public/img/*.webp`, PDF `public/docs/*.pdf`) после запуска на хостинге живёт **на сервере** — его правит клиент в админке. Поток: сервер → сюда (`deploy.php pull`).
- **Код** (шаблоны, стили, скрипты, ядро админки) живёт здесь, в git. Поток: отсюда → сервер (`deploy.php push`). Заливка кода **не трогает** `data/`, фото, PDF и `storage/`.
- HTML-страницы (`index.html`, `roboty.html`, `sady.html`, `politika.html`, `soglasie.html`, `spasibo.html`, `404.html`, `sitemap.xml`, `robots.txt`) — производные, руками не правятся.
- Перед правкой шаблонов у себя — сначала `pull`.

## Быстрый старт

Нужен PHP 8.1+ с `gd` (WebP), `mbstring`, `exif`, `curl`, `ftp`, `fileinfo`. Node 22+ — только для тестов.

```bash
php app/bin/build.php                      # собрать сайт в dist/
php -S 127.0.0.1:8080 app/dev-router.php   # сайт http://127.0.0.1:8080, админка /admin/, заявки /lead.php
php app/bin/admin-setup.php <пароль>       # создать вход в админку (один раз)
```

Локальные настройки — `app/config.local.php` (в git не хранится):
```php
<?php return ['site_url' => 'http://127.0.0.1:8080', 'base_path' => '', 'admin_local_no_gate' => true];
```

## Админка

Адрес входа: `https://домен/admin/<секретное-слово>` → пароль. Без секретного адреса любой адрес `/admin/...` отвечает 404.

- **Главная — теплицы:** первый экран (три цифры), блоки 10×100, устройство и вентиляция, системы, роботизированный уход, каркас, проект 1 га, калькулятор (цены за полублок и разово), этапы, документы (свидетельства + сертификат ИСО), блок заявки (темы формы), меню (общее для всех страниц), SEO главной.
- **Страница «Роботы»:** первый экран и SEO (цифры «10 программ / 6 зарегистрированы» считаются сами), направления (группы и карточки программ, иконка, привязка к свидетельству), робот, «кому полезно». **Страница «Сады»:** шапка, SEO, раздел о проектах садов.
- Любой раздел можно скрыть — вместе с пунктами меню; страницы «Роботы» и «Сады» — целиком, вместе со ссылками и карточками на главной.
- **Компания и контакты** — меняются на всём сайте сразу, включая политику, согласие и микроразметку. Там же адрес сайта для юр. документов (пока пусто — выделенная пометка «[адрес сайта]»).
- **Фото** (загрузка, сжатие в WebP 1280/640, подписи, папки) и **Файлы PDF** (загрузка, проверка, что это PDF; используемый файл не удаляется).
- **Заявки** (тема, культура, задача, UTM), **История правок** (вернуть любую версию), **Корзина** (удалённые фото и PDF), **Настройки** (почта и Telegram для заявок, пароль).
- Если сохранение ломает сайт (например, у программы свидетельство, которого нет в «Документах»), файлы возвращаются как были и админка пишет, что не так.

Вошедший в админку видит на страницах сайта кнопку «✎ Редактировать».

## Хранилище `storage/` (не в git, на сервер не заливается)

Пароль и секретное слово, сессии, попытки входа, заявки (`leads/*.jsonl`), история правок, корзина, настройки отправки заявок. Сброс пароля: `php app/bin/admin-setup.php <новый-пароль>` по SSH или удалить `storage/admin.json`.

## Публикация на хостинг (Beget, Timeweb и т.п.)

Раскладка на сервере (папка сайта, например `~/modufarm.ru`): `app/`, `data/`, `storage/` (создаётся сама), `public_html/` — корень сайта (статика + собранные страницы + заглушки `admin/index.php`, `lead.php`).

1. `app/deploy.local.php` — доступ к FTP (пример `app/deploy.example.php`).
2. `app/config.server.php` — настройки сервера (пример `app/config.local.example.php`): `site_url`, `public_dir`/`out_dir` = `ROOT_DIR . '/public_html'`, длинный случайный `deploy_key` (тот же — в `deploy.local.php`).
3. `php app/bin/deploy.php init <надёжный-пароль>` — зальёт код, данные, фото и PDF, создаст вход в админку и напишет секретный адрес. На сервер с данными не пойдёт.
4. Открыть главную и адрес входа. В админке → «Компания и контакты»: адрес сайта; → «Настройки»: почта/Telegram для заявок, «Отправить проверочную заявку».
5. После выпуска SSL — включить редирект на https в `public/.htaccess` и `push`.
6. Выключить GitHub Pages (иначе будет вторая, устаревшая копия сайта).

Дальше: `php app/bin/deploy.php push [--dry]` — код; `php app/bin/deploy.php pull` — забрать правки клиента и закоммитить.

Проверить на хостинге: PHP веб-сервера ≥ 8.1, применился `.user.ini` (лимиты загрузки), `mail()` с From на домене, доступен `api.telegram.org`, адрес `/admin/...` доходит до `admin/index.php`.

## Превью на GitHub Pages

`.github/workflows/pages.yml` собирает сайт из `data/` и публикует `dist/` (Settings → Pages → Source: GitHub Actions). PHP там не выполняется: форма заявки и админка работают только на хостинге.

```bash
node tests/edits.mjs      # правки, экранирование, откат, отказы, документы с PDF и фото, скрытие раздела, заявки

```
